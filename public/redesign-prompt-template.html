ปรับ layout / component / font / dropdown ให้ตรง prototype design
เพื่อให้ UX ของ ERP มี design language ที่สอดคล้องกัน

## ขอบเขตที่ต้องการแก้
[เลือกข้อที่ต้องการ — ถ้าต้องการครบให้ระบุทั้งหมด]

### 1. Font + Typography
- ใช้ font Inter (English) + Sarabun (Thai) จาก next/font/google
- ขนาด font: input 14px, label 13px font-weight 600, helper 12px
- Apply เฉพาะหน้านี้ (ไม่กระทบหน้าอื่น)

### 2. Layout
- Numbered sections (badge 7×7 emerald + ชื่อไทย/อังกฤษ + เส้นคั่น)
- 2-column grid (sm:grid-cols-2)
- Panel styling: bg-white, rounded-2xl, subtle shadow
- Sub-panels สำหรับ section พิเศษ (สี emerald-50)

### 3. Dropdown (Lookup)
- ใช้ SearchableSelect ที่มีอยู่แล้ว
  (src/components/master-data/SearchableSelect.tsx)
- Click trigger เปิด panel ด้านล่าง
- ช่องค้นหา + magnifier icon
- Highlight match สีเหลือง
- Arrow keys navigate, Enter select, Esc close
- Selected option emerald-50 + Check icon

### 4. Form Components
- Input fields: rounded-[10px], border-slate-200, focus emerald-500
- Helper text ใต้ input (text-xs slate-500)
- Required field: ใส่ * สีแดง
- Toggle cards แทน checkbox (ถ้าเป็น on/off)
- Auto badges (⚡ Auto) สำหรับช่องที่ระบบเติมให้

### 5. Live Preview Panel (optional)
- Sticky ขวามือ (xl:col-span-1)
- Real-time update
- จุดเขียวกระพริบ (animate-pulse)
- Preview content ที่ user/operator จะเห็นจริง

### 6. Sticky Footer (optional)
- Fixed bottom bar
- Status indicator + Cancel/Save buttons

## ข้อจำกัด
- Backwards-compatible — ข้อมูลเดิมต้องแสดงได้
- ไม่กระทบ consumer pages อื่นที่ใช้ component เดียวกัน
- Deploy ทั้ง 5 tenants
  (metaherb + arjaro + renunakhon + huaikoeng + phonphisai)

## ขั้นตอน
1. วิเคราะห์ผลกระทบกับ consumers/schema ก่อน
2. เสนอเป็น Phase ถ้า scope ใหญ่
3. Test pass + type check clean ก่อน commit
4. Update changelog
5. Deploy 5 tenants

Tips ในการเขียน Prompt

✅ ทำให้ทำงานง่าย

  • อ้างอิงหน้าที่ทำเสร็จแล้ว เช่น "เหมือน /master-data/ipc-criteria/new" — AI จะดูโค้ดของหน้านั้นแล้วใช้ pattern เดียวกัน
  • ระบุ scope ชัดเจน — แค่ font? แค่ dropdown? หรือทั้งหมด?
  • บอก deploy targets — "Deploy 5 tenants" หรือเฉพาะที่ต้องการ
  • ระบุข้อจำกัด — backwards-compat, ไม่แตะ consumer

❌ หลีกเลี่ยง

  • "ปรับให้สวยขึ้น" — ไม่ชัดเจนว่าสวยแบบไหน
  • "เหมือนหน้านั้น" โดยไม่ระบุว่าหน้าไหน
  • "ทำให้เสร็จ" โดยไม่ระบุว่าจบที่ commit หรือ deploy
⚠ สำคัญ: ถ้าหน้าที่จะแก้มี schema หรือ consumers หลายตัว ให้บอก AI ตั้งแต่แรกว่า "วิเคราะห์ผลกระทบก่อน" — AI จะทำเป็น phase ที่เล็กลงและปลอดภัยกว่า
