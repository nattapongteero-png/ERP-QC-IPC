📊 สถานะของ Work Order — เปลี่ยนเมื่อบันทึกอะไร

ทุก WO มีสถานะปัจจุบัน 1 สถานะ. การเปลี่ยนสถานะแต่ละครั้งระบบจะเช็ค gate (เงื่อนไขก่อนผ่าน) และบันทึก audit log

สถานะ ความหมาย เปลี่ยนไปสถานะถัดไปเมื่อ เงื่อนไข Gate
Planned
วางแผน		 WO ถูกสร้างใหม่ มี product, BOM, จำนวน, วันที่ผลิต กดปุ่ม "Advance to Released" canRelease — ต้องมี BOM ที่ valid + วัตถุดิบในคลัง
Released
ปล่อยสายผลิต		 Production team รับงาน → เตรียม cleaning, ส่งใบเบิก, ชั่งวัตถุดิบ กดปุ่ม "Advance to In Progress" canStartProduction — Pre-production cleaning + Material weighing เสร็จครบ
In Progress
กำลังผลิต		 Operator กำลังทำ SOP, IPC, packaging กดปุ่ม "Advance to Completed" canCompleteProduction — SOP ทุก step Verified + IPC pass + Finished Inspection pass + บันทึก yield
Completed
เสร็จสิ้น		 ผลิตเสร็จ — มี yield บันทึกครบ, สินค้าเข้า FG warehouse Accounting period close (ทำที่ Accounting module) —
Closed
ปิดงวด		 ปิดบัญชีแล้ว — lock ไม่ให้แก้ไข — Terminal state
Cancelled
ยกเลิก		 ยกเลิกได้ทุกสถานะก่อน Completed (ไม่นับ output) — ไม่มี gate — กดยกเลิกได้เสมอ
⚠ ระบบ block ถ้า gate ไม่ผ่าน: ตัวอย่างถ้ากด "Advance to Released" แต่ยังไม่มี BOM → ระบบขึ้น popup "ยังทำขั้นตอนไม่ครบ" พร้อมรายการ blocker ตามลำดับ

📝 ขั้นตอนการบันทึก Work Order

ตั้งแต่สร้าง WO ใหม่จนปิดงาน — แต่ละ phase ต้องบันทึกข้อมูลอะไรบ้าง

📋
Phase 1: สร้าง WO (Planned)
หน้า /production/work-orders/new

ข้อมูลที่ต้องกรอก:

  • Product — เลือกผลิตภัณฑ์ (Finished Goods หรือ WIP)
  • BOM — เลือก Bill of Materials version ที่ใช้
  • Planned Quantity — จำนวนที่ต้องการผลิต + หน่วย (ขวด/แคปซูล/g)
  • Batch Number — เลข batch ตาม convention
  • Planned Start / End Date — วันที่วางแผนเริ่ม/เสร็จ
  • Priority — 1-10 (1 สำคัญสุด)
  • Notes (optional) — หมายเหตุพิเศษจาก Production Planner

➡ บันทึก → WO เกิดในสถานะ Planned

🚀
Phase 2: เตรียม Released
หน้า /production/work-orders/[id]/execution

ก่อนกดปุ่ม Advance ต้องบันทึก:

  • ส่งใบเบิกวัตถุดิบ — กดปุ่ม "ส่งใบเบิกวัตถุดิบ" → คลังอนุมัติ
  • Pre-Production Cleaning — Mark Clean ห้อง + อุปกรณ์ ตาม BOM + verify (dual-control)
  • Material Weighing — ชั่งวัตถุดิบทุก line ตาม BOM + verify
  • Pre-Production Environmental — บันทึกอุณหภูมิ + ความชื้น

➡ Gate canStartProduction ผ่าน → กด Advance to In Progress

⚙
Phase 3: ระหว่างผลิต (In Progress)
การบันทึกหลายส่วนคู่ขนานกัน

ระหว่างผลิตต้องบันทึกครบ:

  • SOP Execution — ทุก step ตาม BOM (ดู section ถัดไป)
  • Production Cleaning — cleaning ระหว่างผลิตถ้า BOM กำหนด
  • Production Environmental — temp + humidity ทุก interval
  • IPC (In-Process Control) — ทดสอบคุณภาพระหว่างผลิตตาม IPC criteria
  • Bulk Output — บันทึกจำนวนผลิตภัณฑ์บัลก์ (ก่อนบรรจุ)
  • Post-Production Cleaning — ทำความสะอาดหลังจบ production
  • Pre-Packaging Cleaning + Packaging Cleaning — สำหรับห้องบรรจุ
  • Packaging Weight Control — ชั่งน้ำหนัก sample บรรจุ
  • Packaging Integrity Check — ตรวจสภาพบรรจุภัณฑ์
  • Packaging Environmental — temp + humidity
  • Finished Product Inspection — checklist 15 ข้อ
  • Finished Output — จำนวนสินค้าสำเร็จรูป + yield %
✓
Phase 4: ปิด Work Order (Completed)
eBMR + Yield + Sign-off

กดปุ่ม "Advance to Completed" — ระบบ:

  • เช็ค gate ว่าทุก section ทำครบ + verified
  • บันทึก Actual Quantity, Yield %, Production Time
  • บันทึก completedBy + completedAt (eBMR signature)
  • Trigger inventory: เพิ่ม FG ลงคลังตามจำนวน finished output
  • Ready สำหรับ Print eBMR เพื่อจัดเก็บเอกสาร GMP

⚙ ขั้นตอนการบันทึก SOP Execution

SOP Execution คือการบันทึกการปฏิบัติตาม Standard Operating Procedure ระหว่างผลิต — ระบบ initialize SOP steps จาก BOM อัตโนมัติเมื่อ WO สถานะ In Progress

4 Phases ของแต่ละ Step

ทุก step ของ SOP จะเดินผ่าน 4 สถานะแบบลำดับ:

⏰
Phase 1: Pending — รอเริ่ม
สีเทา · icon นาฬิกา

ข้อมูลที่ระบบมีให้แล้ว:

  • Step Name, Sequence Order (ลำดับ)
  • BOM Instructions — คำแนะนำการทำงาน
  • Sub-Steps — checklist แต่ละข้อย่อย (ถ้ามี)
  • Expected Parameters — ค่าเป้าหมาย เช่น Temp 240°C, Time 30min
  • Required Equipment — อุปกรณ์ที่ต้องใช้

Operator ต้องทำ: กดปุ่ม ▶ Start

เงื่อนไข: Step ก่อนหน้าต้อง Completed (หรือ Verified ถ้า require verification)

▶
Phase 2: In Progress — กำลังทำ
สีน้ำเงิน · card highlight

Operator ทำงานจริง + บันทึก:

  • ทำตาม BOM Instructions
  • ติ๊ก checklist sub-steps ครบทุกข้อ (ถ้ามี) — มีปุ่ม "ทำเครื่องหมายทั้งหมด"
  • กดปุ่ม ✓ Complete

ใน Dialog "Complete Production Step" ต้องกรอก:

  • Actual Parameters — ค่าจริงที่ทำได้
    • Temperature: 245 (expected: 240)
    • Time: 28 (expected: 30)
    • Speed: 1500 RPM (expected: 1500)
  • Notes — สังเกตการณ์ / ค่าผิดปกติ / ข้อยกเว้น

ระบบบันทึก operator ID + timestamp เข้า quality_test record อัตโนมัติ

✓
Phase 3: Completed — ทำเสร็จแล้ว
สีเขียว · บันทึกเสร็จ รอตรวจ

ผลที่ได้:

  • ระบบบันทึก operatorId, completedAt, actualParams (JSON)
  • Step ถัดไปยังเริ่มไม่ได้ถ้า step นี้ require verification และยังไม่ verified
  • ป้าย Requires Verification ปรากฏ

ถ้าไม่ require verification → จบที่นี่ ไป step ถัดไปได้เลย

👤
Phase 4: Verified — ตรวจสอบรับรองแล้ว
สีฟ้า · GMP dual-control sign-off

คนอื่น (ไม่ใช่ operator) login → กด 👤 Verify

ระบบบันทึก:

  • verifiedBy = user ที่กด Verify (ต้องไม่ใช่ operatorId)
  • verifiedAt = timestamp การตรวจสอบ
  • Step ถัดไปเริ่มได้แล้ว
⚠ Dual-Control Block: ถ้าคน login ตอน verify เป็นคนเดียวกับ operator → ปุ่ม Verify ไม่แสดง + ขึ้น ⏳ Awaiting other verifier

🛡 GMP Dual-Control Rule

มาตรฐาน GMP กำหนดว่า "คนที่ทำ ≠ คนที่ตรวจสอบ" เพื่อให้มี independent check

สถานการณ์ปุ่ม Verifyป้ายที่แสดง
คุณเป็น operator ของ step นี้ ❌ ไม่แสดง ⏳ Awaiting other verifier
คุณเป็น user คนอื่น (เช่น Supervisor) ✅ แสดง 👤 Verify
Step ไม่ require verification — ไม่ต้อง Verify, จบที่ Completed
💡 Realtime Sync: เมื่อมี user อื่นกด Verify จาก browser อื่น — หน้าของคุณจะ refresh สถานะอัตโนมัติภายใน ~1 วินาที (ไม่ต้องกด refresh manual)

⚠ จุดที่คนพลาดบ่อย

😕 กดปุ่ม Start ไม่ได้
ตรวจ: Step ก่อนหน้า Verified แล้วหรือยัง? ถ้ายัง Completed ก็ยังเริ่มไม่ได้ (ถ้า require verification)
🔍 ไม่มีปุ่ม Verify
คุณคือ operator ของ step นี้ — ต้องให้ user คนอื่น login เข้ามาแทน (GMP dual control)
📝 Sub-steps ยังไม่ติ๊กครบ
ปุ่ม Complete จะใช้ไม่ได้จนกว่าจะติ๊ก checklist ครบทุกข้อ — ใช้ปุ่ม "ทำเครื่องหมายทั้งหมด" ช่วยได้
⚖ Actual ห่างจาก Expected
ระบบไม่ block แต่ควรใส่ Notes อธิบาย เพื่อให้ตอน Verify เข้าใจ
🔄 หน้าไม่ refresh
ระบบ realtime sync ทำงานอัตโนมัติ — ถ้ายังไม่ update ลอง refresh browser หรือเช็คว่า login session ยัง active
🚫 Operator login ผิดคน
ถ้าคน login ที่กด Complete ไม่ใช่คนทำจริง — ตอน Verify จะ block เพราะระบบจำว่า "คน login = operator"
