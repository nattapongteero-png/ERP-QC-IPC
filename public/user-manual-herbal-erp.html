Chapter 1 · Master Data Management

บทที่ 1: การเพิ่มและจัดการข้อมูลพื้นฐาน

ก่อนที่ระบบจะทำงานได้ครบวงจร ต้องมีข้อมูลพื้นฐาน (Master Data) ครบถ้วน ได้แก่ รหัสวัตถุดิบ รหัสบรรจุภัณฑ์ รหัสสินค้าสำเร็จรูป และสูตรการผลิต (BOM) บทนี้จะสอนวิธีสร้างและจัดการข้อมูลพื้นฐานเหล่านี้

🌿Step 1วัตถุดิบRM-XXXX
→
📦Step 2บรรจุภัณฑ์PK-XXXX
→
💊Step 3สินค้าสำเร็จรูปFG-XXXX
→
📋Step 4สูตรผลิต (BOM)ผูก RM+PK → FG

🎯 Quick Reference

Role ที่ใช้ได้Admin, Warehouse, Production
Path หลัก/inventory/items, /production/bom
เวลาที่ใช้~15 นาที/รายการ
ต้องทำก่อนPurchasing, Production
📌
โครงสร้างเมนูที่เกี่ยวข้อง: Inventory → Items ใช้สร้าง รหัสทุกประเภทของ item (Raw Material, Packaging, Consumable, Finished Goods) ในหน้าเดียวกัน โดยใช้ Item Type เป็นตัวแยกประเภท / Production → BOM ใช้ผูกสูตรการผลิต / Production → Master Data ใช้ตั้งเกณฑ์ IPC, ห้องผลิต, เครื่องจักร (ไม่ใช่สำหรับ items)

1.1 การสร้างรหัสวัตถุดิบ (Raw Materials)

วัตถุดิบในระบบ Herbal ERP หมายถึงสมุนไพรสด/แห้ง สารสกัด หรือส่วนประกอบที่ใช้ในการผลิตยาสมุนไพร ทั้งหมดสร้างที่หน้า Items เดียวกัน แยกประเภทด้วย Item Type

1

เข้าเมนู Inventory → Items หรือใช้ /inventory/items

2

กดปุ่ม + สร้างใหม่ (New Item) ที่มุมบนขวา

3

กรอกข้อมูลที่จำเป็น (ช่องที่มี * ห้ามเว้นว่าง):

📝 Form: สร้างวัตถุดิบใหม่
Code *RM-HERB-001
Name (EN) *Turmeric Powder
Name (TH)ผงขมิ้นชัน
Item Type *Raw Material
Primary Unit *kg
Secondary Unitg (1 kg = 1000 g)
CategoryHerbal Powder
4

(ถ้ามี) กำหนด Reorder Point (ระดับสต๊อกขั้นต่ำ) และ Safety Stock เพื่อให้ระบบแจ้งเตือนเมื่อสต๊อกใกล้หมด

5

กด บันทึก (Save)

ผลลัพธ์: รายการใหม่ปรากฏในตาราง Master Data พร้อมสถานะ Active สามารถใช้ในการจัดซื้อและผลิตได้ทันที
💡
Tip: ตั้ง Item Code ให้มี Prefix ที่สื่อความหมาย เช่น RM- = Raw Material, PK- = Packaging, FG- = Finished Goods เพื่อง่ายต่อการค้นหา
⚠️
ข้อระวัง: Primary Unit ควรเป็นหน่วยฐานที่ใช้ในการนับสต๊อก (kg, pcs) ส่วน Secondary Unit ใช้สำหรับรับเข้า/จ่ายออกในหน่วยอื่น ต้องกำหนด Conversion Rate ให้ถูกต้อง ไม่งั้นสต๊อกจะเพี้ยน
📸 หน้าจอระบบ: Inventory → Items — รายการสินค้าทั้งหมด แยกตามแถบ (วัตถุดิบ / บรรจุภัณฑ์ / สินค้าสำเร็จรูป)

1.2 การสร้างรหัสบรรจุภัณฑ์ (Packaging)

บรรจุภัณฑ์และวัสดุสิ้นเปลืองสร้างที่ Inventory → Items เช่นเดียวกัน แต่ต้องเลือก Item Type = Packaging หรือ Consumable

ประเภทItem Typeตัวอย่างPrefix แนะนำ
ขวดยา / ภาชนะบรรจุPackagingขวด PET 100ml, ซองอลูมิเนียมPK-
ฉลาก / กล่องPackagingฉลากผลิตภัณฑ์, กล่องใส่ยาPK-LB-
วัสดุสิ้นเปลืองConsumableผ้ากรอง, ถุงมือ, น้ำยาทำความสะอาดCS-
📌
หมายเหตุ: บรรจุภัณฑ์ที่สัมผัสผลิตภัณฑ์โดยตรง (Primary Packaging) ควรตั้ง isCritical = true เพื่อให้ระบบบังคับทำ QC ก่อนใช้

1.3 การสร้างรหัสสินค้าสำเร็จรูป (Finished Goods)

สินค้าสำเร็จรูป (FG) คือผลิตภัณฑ์ขั้นสุดท้ายที่พร้อมจำหน่าย สร้างที่ Inventory → Items เลือก Item Type = Finished Goods และต้องมีข้อมูลเพิ่มเติม:

1

สร้างรายการแบบเดียวกับวัตถุดิบ แต่เลือก Item Type = Finished Goods

2

กรอกข้อมูลเพิ่มเติมสำหรับ FG:

  • เลขทะเบียนยา (FDA No.) — จำเป็นสำหรับการขาย
  • Shelf Life — อายุการเก็บรักษา (เดือน/ปี)
  • Storage Condition — เงื่อนไขการเก็บ (อุณหภูมิ, ความชื้น)
  • ราคาขาย (Selling Price) — ถ้าทราบ
3

กด บันทึก — ระบบจะสร้างรหัส FG พร้อมให้ไปผูก BOM ในขั้นต่อไป

1.4 การสร้างสูตรการผลิต (Bill of Materials - BOM)

BOM คือสูตรที่บอกว่า "ยา 1 Lot ต้องใช้สมุนไพร / วัตถุดิบอะไรบ้าง อย่างละเท่าไหร่" เป็นหัวใจของการตัดสต๊อกอัตโนมัติและคำนวณต้นทุน

1

เข้าเมนู Production → BOM หรือ /production/bom

2

กด + สร้าง BOM ใหม่

3

กรอกข้อมูล Header:

📝 Form: สร้าง BOM ใหม่
BOM Code *BOM-FG001-V1
สินค้า (Item) *FG001 - ยาขมิ้นแคปซูล
Version *1.0
ขนาด Lot (Batch Size) *1000 capsules
Yield Target %95%
Loss Allowance %5%
4

เพิ่ม BOM Lines (รายการวัตถุดิบที่ใช้) ทีละรายการ:

ItemQtyUnitNote
RM-HERB-001 (ผงขมิ้น)500gสมุนไพรหลัก
RM-HERB-002 (ผงพริกไทย)50gเสริมการดูดซึม
PK-CAP-001 (แคปซูลเปล่า)1000pcsบรรจุภัณฑ์
PK-BTL-001 (ขวด PET)10pcs1 ขวด = 100 แคปซูล
5

(Optional) กำหนด Operations (ขั้นตอนการผลิต) เช่น ชั่ง → ผสม → บรรจุ → ตรวจสอบ

6

กด Approve BOM เพื่ออนุมัติให้ใช้งานในการผลิตได้

ผลลัพธ์: สถานะ BOM เปลี่ยนเป็น Active และสามารถเรียกใช้ในใบสั่งผลิตได้
💡
Tip: ถ้ามีการปรับสูตร (เช่น เปลี่ยนสัดส่วน) ให้สร้าง Version ใหม่ (เช่น V2) แทนการแก้ Version เดิม เพื่อรักษาประวัติการผลิต
🚨
GMP Compliance: BOM เป็นเอกสาร Master Batch Record ทุกการเปลี่ยนแปลงต้องผ่านการอนุมัติจาก QA ตามข้อกำหนด GMP ห้ามแก้ไข BOM ที่ Active โดยพลการ
📸 หน้าจอระบบ: Production → BOM — รายการสูตรการผลิต (Bill of Materials)

❓ คำถามที่พบบ่อย (FAQ)

ถ้าพิมพ์รหัสวัตถุดิบผิดแล้วบันทึกไปแล้ว แก้ไขได้ไหม?
สามารถแก้ไขชื่อ/หมวดหมู่/หน่วย ได้ตลอด แต่ Item Code ห้ามเปลี่ยน ถ้ามีรายการอ้างอิงแล้ว (เช่น เคยใช้ใน PO หรือ BOM) หากต้องเปลี่ยนรหัสจริง ให้สร้างรายการใหม่และ Inactive รายการเดิม
เปลี่ยน BOM จาก V1 เป็น V2 จะกระทบ WO ที่กำลังผลิตไหม?
ไม่กระทบ — WO ที่สร้างก่อน V2 จะยังใช้ V1 ของมันต่อไปจนจบ (snapshot ไว้แล้ว) ส่วน WO ใหม่จะใช้ Version ที่ Active ล่าสุด

2.1 การสร้างใบสั่งซื้อ (Purchase Order)

1

เข้าเมนู Purchasing → Orders หรือ /purchasing/orders

2

กด + สร้าง PO ใหม่

3

เลือก Supplier จาก dropdown (ถ้าไม่มีต้องเพิ่มใน Master Data ก่อน)

4

กรอก Header: วันที่สั่ง, วันที่ต้องส่ง, Payment Terms, ที่อยู่จัดส่ง

5

เพิ่มรายการสินค้าใน Lines: เลือก Item → กรอก Qty → ระบบแสดงราคาต่อหน่วยอัตโนมัติ (จากประวัติล่าสุดหรือราคา Contract)

6

7

ผลลัพธ์: PO อยู่ในสถานะ Pending Approval ผู้อนุมัติจะได้รับการแจ้งเตือน
8

เมื่อ PO ผ่านการอนุมัติ → สถานะเปลี่ยนเป็น Approved → ส่งให้ Supplier ทางอีเมลหรือพิมพ์

💡
Tip: ถ้าต้องสั่งซื้อวัตถุดิบจำนวนมาก ให้ใช้ Purchase Requisition (PR) ก่อน — จะได้ขั้นตอนการอนุมัติและตรวจสอบ budget ได้ก่อนออก PO จริง
📸 หน้าจอระบบ: Purchasing → Orders — รายการใบสั่งซื้อ
📸 หน้าจอระบบ: Purchasing → Orders → สร้างใบสั่งซื้อใหม่

📸 หน้าจอระบบ: Inventory → Lots — รายการ Lot ทั้งหมด แสดงสถานะ Quarantine/Released

2.3 การจัดการ Lot & QC Pass (Release)

1

2

3

4

5

ผลลัพธ์: สถานะ Lot เปลี่ยนจาก Quarantine → Released สามารถเบิกไปใช้ผลิตได้
6

📸 หน้าจอระบบ: Quality → Tests — รายการ QC Test ทั้งหมด

6.1 การทดสอบ (QC Test)

QC Test ใช้บันทึกผลการตรวจสอบคุณภาพของวัตถุดิบ (Incoming), ระหว่างผลิต (In-Process), และสินค้าสำเร็จรูป (Final) โดยเทียบผลกับ Specification อัตโนมัติ

2

กดปุ่ม + สร้าง QC Test ใหม่

3

เลือก Lot ที่ต้องการตรวจ (แสดงเฉพาะ Lot สถานะ Quarantine)

4

เลือกประเภทการตรวจ: Incoming (วัตถุดิบรับเข้า), In-Process (ระหว่างผลิต), Final (สินค้าสำเร็จรูป)

5

บันทึกผลตรวจแต่ละรายการ — ระบบจะเทียบกับ Specification ที่กำหนดไว้อัตโนมัติ

ผลลัพธ์: สถานะ Pass (ผ่าน) หรือ Fail (ไม่ผ่าน) แสดงอัตโนมัติ
6

ถ้า Pass → กด Release เพื่อปล่อย Lot ใช้งาน / ถ้า Fail → กด Reject หรือ สร้าง Deviation

ฟิลด์จำเป็นคำอธิบาย
Test Name✅ชื่อการทดสอบ (เลือกจาก IPC Criteria / Master Data)
Type✅Incoming / In-Process / Final
Lot✅เลือก Lot ที่ต้องการตรวจ (Quarantine)
Result✅ค่าผลตรวจ (ตัวเลข หรือ ข้อความ)
StatusAutoPass / Fail (เทียบกับ Spec อัตโนมัติ)
Dispositionถ้า Failการจัดการเมื่อไม่ผ่าน (Reject / Retest / Deviation)

6.2 ข้อกำหนดการทดสอบ (Specification)

Specification คือเกณฑ์ที่ใช้ตัดสิน Pass/Fail ของ QC Test — กำหนดค่า Min-Max สำหรับแต่ละ Test Name ของแต่ละ Item

1

เข้าเมนู Quality → Specifications หรือ /quality/specs

2

กดปุ่ม + สร้างข้อกำหนดใหม่

3

เลือก Item (วัตถุดิบ หรือ สินค้าสำเร็จรูป) ที่ต้องการกำหนดเกณฑ์

4

กรอก: Test Name, ค่า Min-Max, หน่วย (Unit)

5

ถ้าเป็นค่าสำคัญ เลือก Is Critical = Yes (ค่าที่ห้ามเกินเด็ดขาด)

6

กด บันทึก

ผลลัพธ์: Spec จะถูกใช้อ้างอิงอัตโนมัติเมื่อสร้าง QC Test สำหรับ Item นี้
ฟิลด์จำเป็นคำอธิบาย
Item✅เลือกสินค้าที่ต้องกำหนดเกณฑ์
Test Name✅เช่น Moisture Content, Hardness, Microbial Count
Min Value✅ค่าต่ำสุดที่ยอมรับ
Max Value✅ค่าสูงสุดที่ยอมรับ
Unit✅หน่วย เช่น %, mg, CFU/g
Is Criticalทางเลือกค่า Critical ห้ามเกินเด็ดขาด

6.3 ความเบี่ยงเบน (Deviation / Non-Conformance)

Deviation ใช้บันทึกเหตุการณ์ที่ไม่เป็นไปตามมาตรฐาน เช่น QC ไม่ผ่าน, กระบวนการผลิตผิดปกติ, หรือสภาพแวดล้อมไม่ได้มาตรฐาน — ต้องวิเคราะห์สาเหตุและกำหนดมาตรการแก้ไข/ป้องกัน (CAPA)

1

เข้าเมนู Quality → Deviations หรือ /quality/deviations

2

กดปุ่ม + รายงาน Deviation ใหม่

3

กรอก หัวข้อ และเลือก แหล่งที่มา: Production / Quality / Warehouse

4

เลือก ระดับความรุนแรง: Minor (เล็กน้อย) / Major (ร้ายแรง) / Critical (วิกฤต)

5

บันทึก Root Cause Analysis (วิเคราะห์สาเหตุ), Corrective Action (แก้ไข), Preventive Action (ป้องกัน)

6

กด บันทึก → สถานะ Open → ดำเนินการ → Investigating → แก้ไขเสร็จ → Resolved → ปิด → Closed

ฟิลด์จำเป็นคำอธิบาย
Deviation No.Autoระบบสร้างอัตโนมัติ
Title✅หัวข้อความเบี่ยงเบน
Source✅Production / Quality / Warehouse
Severity✅Minor / Major / Critical
Root Cause✅สาเหตุที่แท้จริงของปัญหา
Corrective Action✅มาตรการแก้ไขปัญหาเฉพาะหน้า
Preventive Actionทางเลือกมาตรการป้องกันไม่ให้เกิดซ้ำ
Due Dateทางเลือกกำหนดส่งมอบการแก้ไข
📸 หน้าจอระบบ: Quality → Deviations — รายการความเบี่ยงเบน แยกตามสถานะ/ความรุนแรง
⚠️
GMP: Deviation ระดับ Critical ต้องได้รับการแก้ไขภายใน 24 ชม. และต้องมี CAPA ครบถ้วนก่อนปิด Deviation — ตามข้อกำหนด GMP/PIC/S

7.1 การจัดการ Role (สิทธิการใช้งาน)

Role คือชุดสิทธิ์ (Permissions) ที่กำหนดว่าผู้ใช้สามารถเข้าถึงเมนูใดบ้าง และทำอะไรได้บ้าง (ดู/สร้าง/แก้ไข/ลบ/อนุมัติ)

1

เข้าเมนู HR → Roles หรือ /hr/roles

2

กดปุ่ม + สร้าง Role ใหม่

3

กรอก: Code (เช่น PROD_OPERATOR), ชื่อ Role (เช่น Production Operator), คำอธิบาย

4

เลือก Permissions ที่ต้องการ — ระบบแสดง Permission เป็นหมวดหมู่ (Inventory, Production, Quality, etc.)

5

กด บันทึก

ผลลัพธ์: Role ใหม่พร้อมใช้งาน สามารถผูกกับ User ได้ทันที
ฟิลด์จำเป็นคำอธิบาย
Code✅รหัส Role เช่น PROD_OPERATOR, QC_MANAGER
Name✅ชื่อ Role เช่น Production Operator
Descriptionทางเลือกคำอธิบายหน้าที่ของ Role
Permissions✅สิทธิ์การเข้าถึงแต่ละเมนู/ฟีเจอร์
StatusAutoActive / Inactive / System
📸 หน้าจอระบบ: HR → Roles — รายการ Role ทั้งหมด พร้อมจำนวน Permission
📌
หมายเหตุ: Role ประเภท System (แสดงเป็นสีม่วง) คือ Role พื้นฐานที่ระบบสร้างมาให้ ไม่สามารถแก้ไขหรือลบได้ เช่น admin, production_manager

7.2 การจัดการผู้ใช้งาน (User Management)

การสร้างบัญชีผู้ใช้และกำหนด Role เพื่อให้ผู้ใช้แต่ละคนเข้าถึงระบบตามสิทธิ์ที่กำหนด — ผู้ใช้ login ด้วย Email + Password

1

เข้าเมนู Users หรือ /users

2

กดปุ่ม + เพิ่มผู้ใช้งานใหม่

3

กรอก: ชื่อ, Email (ใช้เป็น username), Password

4

เลือก Role จากรายการ HR Roles ที่สร้างไว้

5

เลือก Department (แผนกที่สังกัด)

6

กด บันทึก

ผลลัพธ์: ผู้ใช้สามารถ Login เข้าระบบได้ทันทีด้วย Email + Password ที่กำหนด
ฟิลด์จำเป็นคำอธิบาย
Name✅ชื่อผู้ใช้งาน
Email✅ใช้เป็น username สำหรับ login (ห้ามซ้ำ)
Password✅รหัสผ่านเริ่มต้น (ผู้ใช้เปลี่ยนได้ภายหลัง)
Role✅เลือกจาก HR Roles เช่น Production Operator
Departmentทางเลือกแผนกที่สังกัด เช่น ฝ่ายผลิต, ฝ่ายคุณภาพ
StatusAutoActive (เปิดใช้งาน) / Inactive (ปิดใช้งาน)
📸 หน้าจอระบบ: Users — รายการผู้ใช้งานทั้งหมด พร้อม Role และ Department
⚠️
Security: ทุกการเปลี่ยนแปลงในระบบถูกบันทึกใน Audit Log — ห้ามแชร์ Password กับผู้อื่น และควรเปลี่ยนรหัสผ่านเริ่มต้นหลังจาก Login ครั้งแรก
💡
Tip: ถ้าต้องการปิดการเข้าถึงชั่วคราว ไม่ต้องลบ User — เปลี่ยน Status เป็น Inactive แทน จะล็อกอินไม่ได้แต่ประวัติยังอยู่
