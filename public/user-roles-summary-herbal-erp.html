🔑 67 Permission Codes ใน 16 Modules พร้อมคำอธิบาย

💡 Permission Code คือสิทธิ์ระดับ Action (เช่น อ่าน/แก้ไข/อนุมัติ) ในแต่ละ Module ของระบบ — แต่ละ Role จะถูกกำหนดให้มี permission codes หลายตัวรวมกัน เพื่อให้สามารถทำงานตามหน้าที่ได้ครบตามมาตรฐาน GMP
💳 Accounting 7 permissions
ใช้ทำอะไร: ระบบบัญชีครบวงจร — AP/AR, Journal Entries, Fixed Assets, Period Close, 3-Way Matching, Bank Reconciliation, รายงานการเงิน
accounting:readดู AP / AR / Journal / รายงานบัญชี
accounting:writeสร้าง/แก้ไข Invoices + Journal Entries
accounting:approveอนุมัติ Payment / Credit Note
accounting:assetsจัดการ Fixed Assets + Depreciation (ค่าเสื่อม)
accounting:closeปิดงวดบัญชี (Period Close)
accounting:matching3-Way Matching (PO-GR-Invoice) ตรวจความสอดคล้อง 3 เอกสาร
accounting:reconcileกระทบยอดธนาคาร (Bank Reconciliation)
🛠️ Admin 3 permissions
ใช้ทำอะไร: สิทธิ์ดูแลระบบระดับสูง — ตั้งค่าระบบ, ดู Audit Trail, จัดการกลุ่มข้อมูลลับ (PDPA)
admin:systemสิทธิ์ดูแลระบบระดับสูงสุด (Super Admin)
admin:audit_trailดู Audit Trail ทั้งระบบ (ประวัติการเปลี่ยนแปลงข้อมูล)
admin:confidentialจัดการกลุ่มข้อมูลลับ (Confidential Access Groups)
💰 Cost Management 3 permissions
ใช้ทำอะไร: คำนวณต้นทุนสินค้า — Landed Cost (ต้นทุนรวมค่าขนส่ง/ภาษี), Work Centers, ต้นทุนมาตรฐาน
cost:readดูต้นทุน / Landed Cost / Work Centers
cost:writeสร้าง/แก้ไข Landed Cost + Work Centers
cost:approvePost Landed Cost เข้าบัญชี (commit ต้นทุน)
🛡️ GMP Compliance 9 permissions
ใช้ทำอะไร: ระบบปฏิบัติตาม GMP — SOP Documents, Change Control, CAPA, Complaints, Recall, Internal Audit, Sanitation, Stability, PQR
gmp:readดูเอกสาร GMP / CAPA / Complaints
gmp:writeสร้าง/แก้ไขเอกสาร GMP
gmp:approveอนุมัติ Change Control / CAPA / Documents
gmp:auditดำเนินการ Internal Audit
gmp:complaintจัดการข้อร้องเรียนลูกค้า (Complaint handling)
gmp:pqrจัดทำ Product Quality Review (PQR ประจำปี)
gmp:recallดำเนินการเรียกคืนสินค้า (Recall) + แจ้งลูกค้า
gmp:sanitationบันทึกการทำความสะอาด / กำจัดแมลง (Pest Control)
gmp:stabilityศึกษาความคงตัวของผลิตภัณฑ์ (Stability Studies)
👥 HR 4 permissions
ใช้ทำอะไร: ระบบบุคคล — Employees, Positions, Organizations, Training, Health Records, Role Assignment
hr:readดูข้อมูลพนักงาน (View HR data)
hr:writeสร้าง/แก้ไขข้อมูลพนักงาน
hr:adminสิทธิ์ HR ระดับสูง (Full HR administration)
hr:health_staffจัดการ Health Records (ข้อมูลสุขภาพ - ลับ)
📦 Inventory 5 permissions
ใช้ทำอะไร: ระบบคลังสินค้า — Items, Lots, Warehouses, Transactions, Expiry Alerts, Requisitions, Transfers
inventory:readดูข้อมูลสต๊อก / Lots / Transactions
inventory:writeสร้าง/แก้ไขข้อมูล Items, Lots, Warehouses
inventory:adjustปรับปรุงสต๊อก (Inventory Adjustment) — GMP critical
inventory:requisitionอนุมัติใบเบิกวัตถุดิบเข้าผลิต
inventory:transferโอนสต๊อกระหว่างคลัง (Warehouse Transfer)
🐛 Issues (Bug Tracker) 3 permissions
ใช้ทำอะไร: ระบบแจ้งปัญหา / Bug Tracking — รายงาน Bug, Feature Request, Support ticket
issues:readดูรายการ Issues / Bug Tracker
issues:writeแจ้งปัญหา/ข้อเสนอแนะ (ผู้ใช้ทุกคน)
issues:resolveTriage + ปิด Issues (สำหรับ Dev/QA team)
🗂️ Master Data 2 permissions
ใช้ทำอะไร: ข้อมูลแม่ระบบผลิต — IPC Criteria, Rooms, Equipment, SOP Templates, Packaging QC, Environmental Conditions
master_data:readดู IPC Criteria / Rooms / Equipment / SOP
master_data:writeสร้าง/แก้ไข Master Data (IPC, Rooms, Equipment, SOP, Packaging QC, Env. Conditions)
🏭 Production 5 permissions
ใช้ทำอะไร: ระบบผลิต — BOM, Work Orders, Batch Records, Material Weighing, IPC Recording, SOP Execution, FG Receipt
production:readดูข้อมูล WO / BOM / Batch Records
production:writeสร้าง/แก้ไข Work Orders + BOM
production:executeปฏิบัติงานจริง (Weighing, Operations, IPC)
production:approveอนุมัติ Production Records (Supervisor sign-off)
production:completeปิด Work Order + บันทึก FG Receipt
🛒 Purchasing 5 permissions
ใช้ทำอะไร: ระบบจัดซื้อ — Purchase Requisitions, Purchase Orders, Vendor Management, Goods Receipt (GR)
purchasing:readดู PR / PO / Vendors
purchasing:writeสร้าง/แก้ไข Purchase Orders
purchasing:approveอนุมัติใบสั่งซื้อ (Approve PO)
purchasing:receiveบันทึกรับเข้าวัตถุดิบ (Goods Receipt)
purchasing:vendorจัดการข้อมูลผู้ขาย (Approved Vendor List)
🔬 Quality 5 permissions
ใช้ทำอะไร: ระบบควบคุมคุณภาพ — Quality Tests, Specifications, Deviations, Lot Release (Quarantine → Released)
quality:readดูผล QC Tests / Specifications / Deviations
quality:writeสร้าง/แก้ไข QC Tests + Specifications
quality:approveอนุมัติผล QC (Pass/Fail Disposition)
quality:deviationจัดการ Deviation / OOS / CAPA initiation
quality:release⚠ GMP Critical — ปล่อย Lot (Quarantine → Released) เฉพาะเภสัชกร/QA
📊 Reports 3 permissions
ใช้ทำอะไร: ระบบรายงาน — Report Templates, Export Excel/PDF, Dashboard, Custom Reports
reports:readดูรายงานทั้งระบบ
reports:createสร้าง/แก้ไข Report Templates
reports:publishPublish Report Template ให้ใช้ได้ทั้งองค์กร
💵 Sales 5 permissions
ใช้ทำอะไร: ระบบขาย — Sales Orders, Customers, Invoice + DO, Credit Limit, VMI Orders
sales:readดู Sales Orders / Customers
sales:writeสร้าง/แก้ไข Sales Orders
sales:approveอนุมัติ SO / Credit Limit
sales:customerจัดการข้อมูลลูกค้า
sales:invoiceออกใบกำกับภาษี + Delivery Order (DO)
⚙️ Settings 2 permissions
ใช้ทำอะไร: การตั้งค่าระบบ — Company Info, Approval Workflow, Matching Tolerance, System Parameters
settings:readดูการตั้งค่าระบบ
settings:writeแก้ไขการตั้งค่า (Company, Approval Workflow, Matching Tolerance)
🔐 User Management 3 permissions
ใช้ทำอะไร: จัดการผู้ใช้งาน — Create/Edit Users, Assign Roles, Reset Password, Enable/Disable Account
users:readดูรายชื่อผู้ใช้งาน
users:writeสร้าง/แก้ไข User + รีเซ็ตรหัสผ่าน
users:adminกำหนด Role ให้ User + ปิด/เปิดใช้งานบัญชี
🔄 VMI (Vendor Managed Inventory) 3 permissions
ใช้ทำอะไร: Vendor Managed Inventory portal — ซิงก์ข้อมูลสินค้า/ราคา/สต๊อก กับ vendor portal, VMI Orders
vmi:readดูคำสั่งซื้อ VMI / Sync Status
vmi:writeจัดการ VMI Orders + Portal Settings
vmi:syncTrigger manual sync (items/prices/inventory)

⚠️ ข้อสำคัญที่ควรทราบ

  • Sidebar Menu Filter — ใช้ role-mapping.ts แปลง HR Role → Legacy Role (hardcoded ในโค้ด)
  • Fine-grained Permission (67 codes) — กำหนดใน DB แต่ตาราง hr_role_permissions ว่างเปล่า → ยังไม่มีการตรวจ permission ระดับ action
  • Employee Role Assignment — ตาราง hr_employee_roles ว่างเปล่า (พนักงาน 7 คนไม่มีใครเชื่อมกับ user account)
  • 'manager' = catch-all — Director / DIV_HEAD / SECTION_HEAD เห็นทุกเมนูยกเว้น Admin Panel
  • Recommended: ควร migrate matrix นี้เข้า DB (seed hr_role_permissions) เพื่อ configure ได้จาก UI โดยไม่ต้องแก้โค้ด
