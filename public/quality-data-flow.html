2Daily Data Entry Flow (ใช้ทุกครั้งที่มีตัวอย่าง)

ลำดับการบันทึกตั้งแต่ลงทะเบียนตัวอย่าง → ทดสอบ → ลงนาม → ปล่อย → ออก COA → ส่งลูกค้า

1
Register Sample — ลงทะเบียนตัวอย่างใหม่ →
/quality/qc-entry/new
กรอก source (raw_material / wo_batch / customer_return / outgoing_shipment / ...), product, lot#, MFG/EXP/Retest dates, quantity, customer (ถ้า outgoing) → ระบบสร้างเลข QC-YYYY-####
Transactional qc_samples qc_sample_tests (seeded จาก panel)
↓
2
Apply Test Panel — เพิ่ม tests จาก panel →
/quality/qc-entry/[id]
บนหน้า detail กดปุ่ม "Apply Panel" → ระบบ copy tests จาก qc_test_panels ของสินค้านั้นมาเป็น initial state (ทำซ้ำได้ ผลรวมกัน)
Transactional qc_sample_tests
↓
3
Record Results — บันทึกผลทดสอบ →
/quality/qc-entry/[id]
analyst กรอก result value + unit + conclusion (pass/fail) ต่อแต่ละ test → ถ้า fail ระบบ auto สร้าง deviation
Transactional qc_sample_tests.result deviations (auto)
↓
4
Submit for Review — ส่งทบทวน →
/quality/qc-entry/[id]
กดปุ่ม "Submit for Review" → status เปลี่ยน in_test → under_review
State transition
↓
5
Sign-off (21 CFR Part 11) — ลงนาม 3 ชั้น →
/quality/qc-entry/[id]
analyst (ลงนาม Phase 1) → reviewer (กด "Approve" → status=approved) → qa_release (กด "Release" → status=released)
Sign-off 21 CFR Part 11 qc_signatures (immutable)
⚠️ Signatures ลบไม่ได้ — เป็น compliance requirement
↓
6
Generate COA — สร้างใบรับรอง (Phase 4+6) →
/quality/qc-entry/[id] → ปุ่ม "Generate COA"
ตอน sample = released กดปุ่ม Generate COA → ระบบ auto pick template ตาม category (default), copy test results เป็น snapshot, ออกเลข COA
Output document coa_documents coa_test_results (snapshot)
↓
7
COA Review → Approve → Issue →
/quality/coa/[id]
2-tier signature (reviewer + approver) → กด Issue → status=issued → COA ทางการพร้อมส่งลูกค้า
Sign-off (2-tier) coa_signatures (immutable)
↓
8
Download Official PDF + ส่งลูกค้า →
/quality/coa/[id]
กดปุ่ม "ดาวน์โหลด PDF ทางการ" → render Puppeteer → PDF ไม่มี watermark, มี QR + verify URL ฝัง — ส่งให้ลูกค้าผ่าน Outlook/Gmail manual (Phase 8 ในอนาคตจะกดส่งใน-ระบบได้)
PDF + QR coa_print_history (paper trail)
↓
9
Public Verify Portal — ลูกค้าเช็คออนไลน์ (Phase 7) →
/coa/verify/[token] (public — ลูกค้าเข้าจาก QR ใน PDF)
ลูกค้าสแกน QR ใน PDF → เข้าหน้า verify online ดูข้อมูล COA realtime ไม่ต้อง login (ระบบ log การเปิดดูใน coa_print_history)
Public read-only
🚧 Phase 8 (กำลังพัฒนา): ปุ่ม "Send Email" + ผูก COA ↔ Sales Order ใน-ระบบ — ตอนนี้ workflow ยังต้องส่ง email manual ผ่าน Outlook/Gmail

3State Machines — สถานะของแต่ละ entity

เข้าใจสถานะของ qc_samples และ coa_documents ก่อนจะกรอกข้อมูลได้ไม่ผิด

🟡 QC Sample (qc_samples.status)

draft → registered → in_test → under_review → approved → released
(any) → rejected ถ้า fail/reject หรือ oos ถ้าผล out-of-spec ต้อง investigate

🟣 COA Document (coa_documents.status)

draft → review → approved → issued
issued → superseded เมื่อออกใบใหม่แทน หรือ revoked เพิกถอนพร้อม reason

analyst(ลงนาม Phase 1 — lab)(ไม่เปลี่ยน status)
reviewer"Approve"under_review → approved
approver(rare — ส่วนใหญ่ทำผ่าน qa_release)—
qa_release"Release"approved → released

5Production ↔ Quality Integration

เกือบทุก sub-page ของ Work Order ทำหน้าที่ "บันทึก QC ระหว่างผลิต" — แม้อยู่ใน /production/ แต่ data ปลายทาง ไหลเข้าระบบ Quality (ทำให้ trigger deviation, สร้าง qc_sample, ออก COA จาก FG lot ได้)

🔥 4 Trigger สำคัญ Production → Quality

① IPC fail (round 2) → auto-deviation
SOP Execution / IPC page บันทึก fail → retest 1 ครั้ง (ถ้า criteria.maxRetestRounds > 0) → fail อีก → auto-create deviation + qc_sample (linked WO) → ปรากฏใน /quality/deviations พร้อม source='production'
② FG Lot สร้าง → ใช้เป็น QC Sample
Production Output page → operator กรอก qty → ระบบสร้าง FG lot → QA ไป /quality/qc-entry/new → เลือก source='work_order_batch' → เลือก lot ที่เพิ่งสร้าง → apply panel → กรอก final QC
③ Material Weighing variance → Material Return
Material Weighing → operator กรอก actual_qty ≠ required (เกิน tolerance) → auto-create material_return record → routed to warehouse inbox
④ Inspection fail → manual deviation
Finished Inspection → 15 checks → fail บางข้อ → prompt operator กดสร้าง deviation manually → link to /quality/deviations
