2Flow ทีละขั้นตอน — Status Lifecycle

submitted──[vendor confirm]──▶ confirmed──[vendor ship]──▶ shipped──[hospital receipt]──▶ received

แต่ละ status เปลี่ยนได้เฉพาะฝ่ายที่มีสิทธิ์ — vendor เปลี่ยน submitted → confirmed → shipped, hospital เปลี่ยน shipped → received ผ่าน goods receipt

3Step 1: HOSxP → VMI Portal (Push PO)

Endpoint ที่ HOSxP เรียก:

POST https://vmi-portal.bmscloud.in.th/api/external/hosxp/orders
Headers:
  X-API-Key: vmi_hosp_<HOSPITAL_CODE>_xxx
  Content-Type: application/json

Body:
{
  "orders": [{
    "localCode": "HSP-001-2026-0042",
    "warehouseLocalCode": "WH01",
    "poNumber": "PO-2026-001",
    "localVendorCode": "V-METAHERB",
    "orderDate": "2026-04-27",
    "expectedDeliveryDate": "2026-05-04",
    "status": "submitted",
    "totalValue": 25000,
    "items": [{
      "localCode": "FAT-001",
      "quantityOrdered": 100,
      "unitPrice": 250,
      "lineTotal": 25000
    }]
  }]
}

VMI Portal ทำอะไรเมื่อรับ:

  1. Validate hospital API key → รู้ hospitalCode อัตโนมัติ
  2. Map localVendorCode → ตาราง hospital_vendor → ได้ portal's vendor_id = 52 (METAHERB)
  3. Map item.localCode → portal's item.id (ผ่าน item sync ที่ทำไว้ก่อน)
  4. INSERT purchase_order + purchase_order_item
  5. Queue webhook event order.created ลง vendor_webhook_delivery
⚠ ก่อน HOSxP push PO ได้ ต้องทำสิ่งเหล่านี้ก่อน:
  • โรงพยาบาลลงทะเบียน vendor ใน portal — ระบบสร้าง row hospital_vendor ผูก localVendorCode ↔ vendor_id
  • HOSxP sync items กับ portal (ผ่าน POST /api/external/hosxp/items) เพื่อให้ item.localCode มีตัวตน

4Step 2: VMI Portal → Herb ERP (2 modes)

📨 Mode A: Webhook (push)
  • ERP ลงทะเบียน webhook URL ผ่าน POST /api/external/vendor/webhooks + เลือก subscribe events order.created
  • เมื่อมี PO ใหม่ portal queue delivery → background worker POST ไปที่ ERP webhook URL
  • มี HMAC-SHA256 signature ใน header X-Webhook-Signature เพื่อ verify ความถูกต้อง
  • Retry 5 ครั้งแบบ exponential backoff ถ้า fail
⏰ Mode B: Polling (pull) ใช้งานจริง
  • ERP มี cron /api/purchasing/vmi/cron/poll-orders ทำงานทุก order_poll_interval_minutes (default 15 นาที)
  • ERP เรียก GET https://vmi-portal.bmscloud.in.th/api/external/vendor/orders?status=submitted ส่ง header X-API-Key: vmi_vend_VEN-0010_…
  • Portal ตอบกลับ orders ที่ vendor_id = 52 เท่านั้น (filter จาก API key auto)
  • ERP เปรียบเทียบกับ vmi_orders.vmi_order_id ที่มีอยู่ → INSERT รายการใหม่
  • ดึง detail แยก: GET /orders/:id → INSERT vmi_order_lines

5Step 3: ERP ดำเนินการ (vendor side)

UI: /purchasing/vmi (Dashboard) → คลิก order → /purchasing/vmi/orders/[id]

3.1 ✅ Confirm Order

ERP เรียก service.confirmOrder(orderId) → ส่ง PATCH /orders/:id body {"action":"confirm"}

  • Portal เปลี่ยน status submitted → confirmed
  • Portal log transaction
  • ERP บันทึก vmi_orders.confirmed_at
3.2 🏭 ผลิต / เตรียมสินค้า

ใช้ flow ปกติของ ERP (Work Order, Production)

  • (ทางเลือก) สร้าง Sales Order หรือ Work Order จาก vmi_order
  • field local_po_id ใน vmi_orders ใช้ link กลับไปยัง local PO/SO ของ ERP
3.3 🚚 Ship Order

PATCH /orders/:id body {"action":"ship", "expectedDeliveryDate":"2026-05-04"}

  • Portal เปลี่ยน status confirmed → shipped
  • ERP บันทึก vmi_orders.shipped_at

6Step 4: รับสินค้า + ปิด loop

HOSxP บันทึกการรับสินค้า → push ไป Portal

POST /api/external/hosxp/receipts
{
  "receipts": [{
    "poLocalCode": "HSP-001-2026-0042",
    "items": [{
      "localCode": "FAT-001",
      "quantityReceived": 100,
      "lotNumber": "L240427",
      "expiryDate": "2027-04-27"
    }]
  }]
}

Portal ทำ:

  1. INSERT goods_receipt
  2. ถ้ารับครบทุก item → purchase_order.status = 'received'
  3. (อาจ) trigger webhook order.received

ERP รอบ poll ถัดไป:

  • เห็น status = received → UPDATE vmi_orders.status + received_at
  • ปิด loop การส่งสินค้า

8การยืนยันตัวตน + API Keys

API keys มี 2 ประเภท แยกกันชัดเจน — endpoint ตรวจสอบประเภท key ที่ส่งมาเทียบกับ endpoint ที่เรียก ถ้าไม่ตรงจะ 403 Forbidden

TypeFormatใช้ที่ endpoint
Hospital vmi_hosp_<HOSP_CODE>_<32_hex> /api/external/hosxp/*
Vendor vmi_vend_<VENDOR_CODE>_<32_hex> /api/external/vendor/*
🔐 API Key isolation: ทุก endpoint ของ portal filter by vendor_id หรือ hospital_code auto จาก key ที่ส่งมา — vendor หนึ่งจะเห็นแต่ orders ของตัวเองเท่านั้น

การเก็บ Key

  • Portal side: เก็บเป็น SHA-256 hash + key_prefix 8 ตัวแรก (เพื่อ index lookup ก่อน hash compare)
  • ERP side: เก็บใน vmi_portal_config.api_key_encrypted — encrypted ด้วย AES (บางตัวเป็น legacy plaintext รองรับได้)

9การตั้งค่าเริ่มต้นสำหรับ Vendor ใหม่

ฝั่ง VMI Portal:

  1. Login เป็น admin ที่ vmi-portal.bmscloud.in.th/vendors
  2. สร้าง vendor record (กรอกชื่อ, code) → ระบบ auto-generate VEN-xxxx
  3. สร้าง API Key ใหม่ → ระบบโชว์ plaintext key ครั้งเดียว ต้อง copy ทันที

ฝั่ง Herb ERP:

  1. เข้า /settings/vmi ของ tenant
  2. ใส่ Portal URL: https://vmi-portal.bmscloud.in.th/
  3. Paste API Key ที่ copy จาก step 3
  4. กด Save → ระบบ test connection (status เปลี่ยนจาก disconnected → connected)

ฝั่งโรงพยาบาล (HOSxP):

  1. โรงพยาบาลลงทะเบียน vendor ในระบบ HOSxP — กำหนด localVendorCode
  2. VMI Portal admin สร้าง row ใน hospital_vendor เพื่อ map (hospital_code, localVendorCode) → vendor_id
📋 Status ปัจจุบัน (Metaherb VEN-0010):
  • VMI Portal: ✅ vendor active, API key id=14 ("metahearb")
  • Herb ERP Metaherb: ✅ vmi_portal_config connected
  • โรงพยาบาลที่จะส่ง PO: ต้องสร้าง row ใน hospital_vendor ของ portal เพื่อ map รหัส vendor ของ HOSxP

10Debug + Troubleshoot

อาการสาเหตุที่เป็นไปได้วิธีตรวจ
PO จากโรงพยาบาลไม่เข้า ERP HOSxP ไม่ได้ push / portal ไม่ได้ map vendor / ERP ไม่ poll เช็ค purchase_order ที่ portal vs vmi_orders ที่ ERP
ERP ไม่ poll cron ไม่ทำงาน / ตั้ง order_poll_interval_minutes นานเกินไป ดู vmi_transactions ที่ /purchasing/vmi/transactions
HTTP 403 จาก portal Vendor ไม่มี API Key / Key ผิด / Key ถูกเพิกถอน เช็ค vendor_api_key ที่ portal
HTTP 401 ส่ง key ประเภทผิด (vendor key ไปยิง hospital endpoint หรือกลับกัน) ตรวจ URL กับ prefix key ให้ตรง
Webhook ไม่ส่ง Vendor ไม่มี webhook subscription / disabled by failures ดู vendor_webhook_delivery.status
HOSxP push ไม่ผ่าน localVendorCode ไม่ match / item ยังไม่ sync / format ผิด ดู container logs ของ vmi-portal-app
🛠 SQL queries ที่ใช้บ่อย 
# Portal: ดู PO ล่าสุดของ vendor
SELECT po.id, po.po_number, po.status, h.hospital_name, po.total_value
FROM purchase_order po
JOIN hospital_code h ON po.hospital_code = h.hospital_code
WHERE po.vendor_id = 52
ORDER BY po.created_at DESC LIMIT 10;

# Portal: ดู API keys ของ vendor
SELECT vak.id, v.code, v.name, vak.name AS key_name, vak.is_active
FROM vendor_api_key vak JOIN vendor v ON vak.vendor_id = v.id
WHERE v.code = 'VEN-0010';

# ERP: ดู vmi_orders ที่ poll มาแล้ว
SELECT id, vmi_order_id, hospital_name, po_number, status, order_date
FROM vmi_orders ORDER BY id DESC LIMIT 10;

# ERP: ดู transaction logs (call ทุกครั้งที่ ERP คุยกับ portal)
SELECT id, transaction_type, status, http_status_code, error_message, created_at
FROM vmi_transactions ORDER BY created_at DESC LIMIT 20;
